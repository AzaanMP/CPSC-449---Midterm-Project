# CPSC-449---Midterm-Project
# 🎟️ Event Ticketing System
### CPSC-449 Midterm Project

A RESTful event ticketing backend built with **Spring Boot**, **Spring Data JPA**, and **PostgreSQL**. The system supports creating events, managing venues and organizers, booking tickets, and tracking revenue.

## 🗂 Data Model
```
Organizer ─────────┐
                   ▼
Venue ────────► Event ◄───── TicketType ◄───── Booking ◄───── Attendee
```

| Entity | Key Fields |
|---|---|
| **Organizer** | `organizerId`, `name`, `email` |
| **Venue** | `venueId`, `name`, `city` |
| **Event** | `eventId`, `title`, `description`, `eventDate`, `status` (UPCOMING / ONGOING / CANCELLED / COMPLETED) |
| **TicketType** | `ticketTypeId`, `name`, `price`, `quantityAvailable` |
| **Attendee** | `attendeeId`, `name`, `email` |
| **Booking** | `bookingId`, `bookingReference` (e.g. `TKT-2026-00001`), `bookingDate`, `paymentStatus` (PENDING / CONFIRMED / CANCELLED) |

| Method | Endpoint | Description |
|---|---|---|

\`\`\`

## 🚀 Getting Started

### Prerequisites

- **Java 25** or later
- **PostgreSQL** running locally on port `5432`
- **Maven** (or use the included `./mvnw` wrapper)

### 1. Set Up the Database

Connect to your PostgreSQL instance and create the database:

\`\`\`sql
CREATE DATABASE ticketing_db;
\`\`\`

> The schema is auto-generated by Hibernate on first run (`ddl-auto=update`).

### 2. Configure Credentials

Update `src/main/resources/application.properties` with your PostgreSQL credentials:

\`\`\`properties
spring.datasource.url=jdbc:postgresql://localhost:5432/ticketing_db
spring.datasource.username=your_username
spring.datasource.password=your_password
\`\`\`

### 3. Run the Application

Using the Maven wrapper (no local Maven install needed):

\`\`\`bash
# macOS / Linux
./mvnw spring-boot:run

# Windows
mvnw.cmd spring-boot:run
\`\`\`

Or if Maven is installed globally:

\`\`\`bash
mvn spring-boot:run
\`\`\`

The server starts on **`http://localhost:8080`**.

### 4. Test the API

You can use [Postman](https://www.postman.com/), [Insomnia](https://insomnia.rest/), or `curl`.

\`\`\`bash
# Create an organizer
curl -X POST http://localhost:8080/api/organizers \
  -H "Content-Type: application/json" \
  -d '{"name": "Alice", "email": "alice@example.com"}'

# List upcoming events
curl http://localhost:8080/api/events
\`\`\`

## ⚙️ Configuration

All configuration lives in `src/main/resources/application.properties`:

\`\`\`properties
# Database
spring.datasource.url=jdbc:postgresql://localhost:5432/ticketing_db
spring.datasource.username=postgres
spring.datasource.password=your_password
spring.datasource.driver-class-name=org.postgresql.Driver

# JPA / Hibernate
spring.jpa.database-platform=org.hibernate.dialect.PostgreSQLDialect
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true

# Server
server.port=8080
\`\`\`

## ⚠️ Error Handling

The API uses a `GlobalExceptionHandler` to return consistent error responses:

| Exception | HTTP Status | Trigger |
|---|---|---|
| `ResourceNotFoundException` | `404 Not Found` | Entity doesn't exist |
| `TicketSoldOutException` | `400 Bad Request` | No tickets remaining |
| `DuplicateBookingException` | `409 Conflict` | Attendee already booked this ticket type |
| `IllegalArgumentException` | `400 Bad Request` | Invalid operation (e.g., cancelling already-cancelled booking) |

## 🏗️ Suggested Setup Order

When using the API for the first time, create resources in this order to satisfy foreign key dependencies:

\`\`\`
1. POST /api/organizers   → get organizerId
2. POST /api/venues       → get venueId
3. POST /api/events       → (uses organizerId + venueId)
4. POST /api/attendees    → get attendeeId
5. POST /api/bookings     → (uses attendeeId + ticketTypeId)
\`\`\`
